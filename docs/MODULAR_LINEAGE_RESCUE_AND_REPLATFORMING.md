# 仿生设计谱系保留、失败定位与材料再平台化规约

状态：`main` 约束性规约，2026-08-02 生效。该规约不降低 Gate A/B/C、E1/E2、创新性、证据或工程门槛，只修正“一个材料实现失败导致整条高价值思路被连带淘汰”的状态管理问题。

## 1. 为什么需要设计谱系

一套方案同时包含环境问题、生物原型、转译原则、材料实现、合成路线和实验释放六个层次。后四层不是同一个对象。一个高精度 COF、梯度壳层或复杂人工识别单元无法制造，只能直接否定该材料实现或合成路线；除非攻击结果同时证明上游原型、功能抽象或选择性逻辑错误，否则不能把整个仿生思路写成“终止”。

项目仍以完整方案通过三道 owner gate 为正式释放条件。模块保留不是候选晋级、性能背书或降低门槛，而是保存可复用的、证据边界清楚的研究资产，使后续材料设计从已经验证的上游模块继续，而不是重复搜索或被一个非唯一实现绑死。

## 2. 三个对象必须分开

### 2.1 设计谱系

设计谱系由以下三项共同定义：冻结的污染物—环境问题、一个有证据的主生物原型、一个具体且可证伪的可转译功能原则。谱系不绑定某一种载体、单体、孔结构或合成路线。

### 2.2 材料实现

材料实现是把同一功能原则落到确切人工材料上的一种答案。不同实现必须在材料类别、空间构造方法或制造原理上实质不同，不能只改配比、孔径或材料名称。

### 2.3 实验释放

E0/E1/E2只描述当前材料实现的实验就绪程度，不描述整个设计谱系是否值得保留。上游模块被保留，不会让任何新材料继承旧材料的分数、E1状态或实验许可。

## 3. 六模块台账

每次攻击和Reviewer裁决必须逐项填写：

| 模块 | 必须回答的问题 | 可用状态 |
|---|---|---|
| `SP` 场景与工程问题 | 二级出水场景、目标、竞争障碍和传统能力缺口是否成立 | `retained` / `conditional` / `invalid` |
| `BP` 生物原型 | 生物功能是否真实、必要且证据边界清楚 | `retained` / `conditional` / `invalid` |
| `TR` 转译原则 | 是否抽象出不依赖特定材料名称、可测量且可做因果对照的功能规则 | `retained` / `revise` / `invalid` |
| `ME` 材料实现 | 当前确切材料能否实现TR并区别于普通吸附 | `advance` / `repairable` / `embodiment_rejected` |
| `SR` 合成路线 | 普通实验条件下是否安全、可操作、可质控、可放大 | `bench_ready` / `revise` / `route_rejected` |
| `ER` 实验释放 | 当前实现是否达到E0、E1或E2 | `lead_only` / `concept_valid` / `E1_ready` / `E2_ready` / `control_only` |

Reviewer还必须写出：最早断裂模块、该断裂是否向上游传播、保留模块、被否决的确切对象、下一种可区分实现或停止理由。

## 4. Reviewer只能作六类处置

1. `advance_current_embodiment`：当前实现继续进入下一门。
2. `repair_current_embodiment`：缺口可在不改变P2和材料身份的情况下关闭。
3. `reject_embodiment_retain_lineage`：材料或合成失败，SP、BP和TR保留，进入再平台化。
4. `retain_prototype_retranslate`：SP/BP保留，但当前TR过度具体、错误或不可检验，重新抽象功能原则。
5. `retain_as_control`：不承担仿生主张，但保留为工程或机制基准。
6. `terminate_lineage`：只有P0、P1或P2本身无效，存在不可消除的项目范围冲突，核心主张已被先例完整占据，或有记录的有界搜索已经耗尽时使用。

新文件不得用无修饰的`terminated`同时指代材料实现和整个谱系。历史文件保持不改写，后续引用时必须按本规约重新解释。

## 5. 何时必须再平台化

同时满足以下条件时，不能因首个材料失败就关闭谱系：

- SP与BP已经由当前证据保留；
- TR具体、必要、可测量，并可设计删除或错配对照；
- 当前失败局限于材料类别、空间精度、成型、合成安全、放大或质量控制；
- 仍存在材料学上实质不同的实现空间；
- 新实现不会靠降低选择性、创新性、场景或安全门槛续命。

再平台化不设固定候选数量。至少要比较一次“高保真但制造脆弱”的实现与“制造优先但功能仍完整”的实现，或者书面证明为什么不存在后者。若多个实现共享同一不可制造假设，它们不算独立备份。

以下情况不启动材料再平台化：场景门失败、原型证据失败、可转译原则只能靠材料名称成立、目标功能可被普通物化参数完整解释、项目范围本身排除该机制，或最近先例已占满核心论文主张。此时应补证、重新抽象或终止谱系，而不是换载体。

## 6. 失败必须按传播范围处理

- `SR`失败通常只否决合成路线；可换路线或材料平台。
- `ME`失败通常只否决当前材料实现；若失败证明TR在人工材料中不可测，才向TR传播。
- 因果对照显示完整体与错配体无差异时，先判断是制造没有实现TR，还是TR本身无功能。两者不得混写。
- TR失败可以保留SP/BP并重新转译；不能把一个错误人工结构反推为生物原型无价值。
- BP或SP失败会使谱系失去本项目准入基础，但相关化学仍可保留为C类理性设计或工程对照。

## 7. 设计韧性与单点失效审计

E1包除现有停止规则外，必须列出：

- 对论文主张最危险的三个单点失效；
- 每个失效首先击穿TR、ME、SR还是仅击穿性能目标；
- 失败后哪些证据资产仍可使用；
- 是否存在保持同一P2的低复杂度实现；
- 何种结果要求收窄主张，何种结果要求停止整个谱系。

正式排序仍不以总分补偿硬门。设计韧性用于判断资源配置和后备路径，不创造新的分数，也不要求为了凑备份而保留弱方案。

## 8. 潘尧审阅视角的使用边界

潘尧提供的经验作为补充审阅视角，不作为设计者的先验模板。为减少锚定和创造力收缩，使用顺序固定为：

1. 设计者先依据项目合同独立冻结SP、BP、TR和第一批材料实现；
2. 攻击者完成一次不读取该经验清单的证据、机制和先例攻击；
3. 再启动补充审阅，使用以下视角提出问题；
4. Reviewer依据证据裁决，经验清单本身不能直接改变状态。

补充审阅包含：

- 领域研究者视角：仿生转译、环境安全、数据和论文逻辑；
- 初学实验者视角：步骤是否能照做、危险点、异常处理和废物处置；
- 合成专家视角：反应机理、计量、加料顺序、副反应、堵孔、质控和放大；
- 全局一致性视角：设计依据、规格、合成、表征、再生和知识映射是否相互一致；
- 六环链论文视角：难题—原型—机制—材料—合成—工程是否逐环闭合。

经验中的具体案例，例如某种偶联体系、磁性增重、强酸强碱或后修饰堵孔，只能作为需要核查的问题生成器。每个化学判断必须针对实际溶剂、底物、浓度、设备和文献重新验证，不能把案例写成跨体系禁令。

## 9. 审阅输出最小模板

```text
lineage_id:
release_status:
SP_scenario_problem:
BP_biological_prototype:
TR_transfer_rule:
ME_material_embodiment:
SR_synthesis_route:
first_broken_module:
failure_propagation:
retained_assets:
reviewer_disposition:
replatform_trigger_or_stop_reason:
single_point_failures:
```

任何再平台化方案必须新建材料身份、对照、合成审查和E1记录；不得继承原实现的分数、通过状态或未验证性能。
